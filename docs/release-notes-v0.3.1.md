# campus-auth v0.3.1

> 修复版：解决两个会静默误导用户的问题（配置被重置、假重启），并补齐 CAS HTTPS、
> 多网卡探测、测试隔离与发布可复现；同时新增新门户探测指纹（阶段 0，为成都工业学院等
> 后续适配做准备，本版本不含新的认证引擎）。

## 🐛 正确性修复

### 配置不再被静默重置（重要）

- 「门户地址」现在是配置界面唯一数据源：打开窗口时显示完整地址（含协议与非默认端口）
- 修复 v0.3.0 的问题：HTTPS / 非 80 端口配置在打开配置窗口后被自动保存成 `http:80`
- 地址为空、端口非法时给出明确的中文提示，而不是静默写回旧值

### 「假重启」修复

- 后台保护进程的启动改为三态结果：已在运行 / 本次启动 / 启动失败
- 旧保护进程无法停止时（缺少 `watch.pid` 的升级残留）明确提示用户结束残留进程，
  不再误报「保护已重新启动，新配置已生效」
- 配置界面与托盘菜单同步修复

### CAS 支持 HTTPS 门户

- CAS 登录 URL、Referer、Origin 改为按画像协议（`portal.scheme`）生成，不再写死 `http`

### 多网卡探测更准

- NCSI 联网探测与 HTTPS 可达探测会绑定配置的网卡，避免有线 + Wi-Fi 同时在线时走错网卡误判

### 版本标识

- 各模块 User-Agent 统一为 `campus-auth/<版本号>`，版本号从 `campus_auth.__version__` 自动读取
  （不再写死 `0.1`）

## 🔍 门户探测增强（阶段 0）

- 新增厂商指纹：锐捷 ePortal（`InterFace.do` 系）、H3C iMC、安朗/安腾（蓝蝴蝶）
- 探测结果新增 `vendor` 与 `suggested_auth_mode` 字段（仅提示，不改变现有三种认证模式的行为）
- `portal.json` 新增 `login` 段骨架（接口/字段/密码变换/服务后缀等），供后续厂商引擎使用
- 说明：本版本**不包含**这些新厂商的认证引擎，实际适配仍需现场取证后进行

## 🔒 测试与工程化

- 测试隔离：日志写入临时目录；画像测试不再读取本机真实 `portal.json`
  （此前跑测试会向 `~/.campus-auth/auth-debug.log` 追加内容）
- 新增回归测试：配置地址往返、守护启动三态、CAS 登录 URL 协议、NCSI 网卡绑定等
- 测试数量 135 → 171 项，全部不触网
- 全项目 `ruff check` 0 告警（此前配置存在但从未执行）

## 📦 发布可复现

- 新增 `requirements-build.txt`：钉死构建依赖（PyInstaller 6.22.3 / pycryptodome 3.24.1）
- 新增单文件版构建 spec（`campus_config_onefile.spec`），单文件发布物可复现
- 发布 zip 内附 `LICENSE`、`README.md`、`portal.example.json`，并生成 `SHA256SUMS.txt`
- `build.ps1` 构建前自动安装完整依赖，避免干净环境构建出缺少 Crypto 的 exe

## 下载

- **`campus-auth-v0.3.1.zip`**（推荐，目录版，约 17 MB）
- `campus-auth-v0.3.1-单文件版.exe`（便携单文件，免解压；首次启动稍慢）

## 升级说明

- 解压覆盖 `_internal` 与 `campus-auth.exe`，**不要删除同目录下的 `portal.json`**
- 若之前配置过 HTTPS 或非 80 端口，请打开配置界面确认门户地址是否正确
  （v0.3.0 可能已将其重置为 `http:80`）

## 注意事项

- 无需安装 Python，独立运行
- 若杀毒软件提示，请添加信任
- 旧日志可能含历史敏感内容，建议删除一次：`~/.campus-auth/auth-debug.log`
